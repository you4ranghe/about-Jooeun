# 08. 모바일 — 서재를 버리고 아이폰 홈 화면으로

> **상태: 확정 (2026-07-31).** §5 의 세 가지가 전부 권장안으로 정해졌습니다.
>
> | | 정한 것 |
> | --- | --- |
> | Q1 주소 | **주소 없이 연다.** 새 라우트 0개. 이미 있는 것(프로젝트·캘린더·음악)만 씀 |
> | Q2 상세 모양 | **전체화면 앱.** 상태 표시줄 + 내용 + 홈 인디케이터 |
> | Q3 세로 서재 | **지운다.** 820×1440 무대는 쓸 자리가 없어짐 |

---

## 1. 왜 방을 버리는가

세로 무대(820×1440)를 만들어 방을 세워 봤지만 **시계·모니터·벽 세 가지가 전부 틀어졌습니다.**
좌표를 하나씩 고치는 방법도 있지만, 고쳐도 남는 문제가 둘입니다.

**(1) 모니터가 세로로 섭니다.** 모니터 화면은 뷰포트와 같은 비율이라야 줌인이 맞습니다.
세로 폰에서 그 비율은 0.46 이라 모니터가 벽의 절반을 차지합니다.
방을 보여주려고 만든 화면인데 방이 안 보입니다.

**(2) 손가락은 카메라를 모릅니다.** 서재의 재미는 "물건을 눌러 카메라가 다가가는 것"입니다.
폰에서는 화면이 작아 다가갈 여지가 없고, 두 손가락 확대와도 부딪칩니다.

**폰에는 폰의 은유가 있습니다.** 방문자가 이미 들고 있는 것이 폰이므로,
화면 안에 또 다른 기기를 그리는 대신 **그 폰인 척**하는 쪽이 자연스럽습니다.

> 데스크톱 서재는 **그대로 둡니다.** 이 문서는 좁은 화면에만 적용됩니다.

---

## 2. 무엇을 바꾸고 무엇을 지키나

| | 데스크톱 (지금) | 모바일 (새로) |
| --- | --- | --- |
| 첫 화면 | 서재 | **아이폰 홈 화면** |
| 프로젝트 | 모니터 → 바탕화면 아이콘 → 브라우저 창 | **홈 화면 앱 아이콘 → 앱** |
| 상세 내용 | 결정 대장 (그대로) | **결정 대장 (그대로)** |
| 시계 | 책상 위 탁상시계 | 홈 화면 위젯 |
| 날씨 | 창밖 | 홈 화면 위젯 + 배경 |
| 음악 | 아이패드 | 앱 |
| 캘린더 | 벽걸이 | 앱 |
| 이력서 · 소개 | 벽에 붙인 메모 | 앱 |

**상세페이지 여섯 장은 한 줄도 바뀌지 않습니다.** 창틀만 갈아 끼웁니다 —
데스크톱은 브라우저 창, 모바일은 앱 화면.

## 3. 홈 화면

```
┌────────────────────────────┐
│  9:41              ▮▮ 100% │  상태 표시줄 — 실제 KST
│                            │
│  ╭──────────╮ ╭──────────╮ │
│  │  09:41   │ │  ☀ 27°   │ │  위젯 둘
│  │  월 7.31 │ │  서울·맑음│ │  진짜 시각 · 진짜 날씨
│  ╰──────────╯ ╰──────────╯ │
│                            │
│  ▢    ▢    ▢    ▢          │
│ 윷놀이 인터페 불멍  MomsUp   │  프로젝트 6
│                            │
│  ▢    ▢                    │
│ 점메추 홈노트                │
│                            │
│  ▢    ▢    ▢    ▢          │
│ 캘린더 음악  이력서  소개     │  기능 4
│                            │
│         ● ○                │
│ ╭────────────────────────╮ │
│ │  ▢       ▢       ▢     │ │  독 — GitHub · 메일 · 이 사이트
│ ╰────────────────────────╯ │
└────────────────────────────┘
```

### 아이콘은 이미 있습니다

바탕화면에 쓰던 SVG 여섯 개를 그대로 씁니다(`components/desktop/IconArt.tsx`).
윷놀이는 그 앱의 진짜 아이콘, 점메추는 저장소의 `icon.svg`,
나머지는 그 사이트 팔레트로 그린 것 — **모서리만 iOS 비율(22%)로 둥글립니다.**

새로 그릴 것은 넷입니다: 캘린더 · 음악 · 이력서 · 소개.

### 위젯이 두 개인 이유

시계와 날씨를 앱으로 만들면 **눌러야 보입니다.** 그런데 이 둘은
"이 사이트가 살아 있다"를 첫 화면에서 보여주는 것이 전부입니다.
누르기 전에 이미 진짜 시각과 진짜 서울 날씨가 돌고 있어야 값을 합니다.
아이폰에서도 시계·날씨는 위젯 자리입니다.

### 배경

방의 창밖과 같은 `useSky` 를 씁니다. **실제 서울 시각과 날씨를 따라**
아침·한낮·해질녘·밤의 그라디언트가 바뀌고, 비나 눈이면 가라앉습니다.
사진 파일은 쓰지 않습니다(docs/04).

---

## 4. 앱을 여는 방식

아이콘을 누르면 **그 아이콘 자리에서 화면이 커집니다.** 데스크톱 창과 같은 수법이고
(`BrowserWindow` 의 FLIP), iOS 가 앱을 여는 방식이기도 합니다.

앱 화면 위쪽에는 상태 표시줄이 그대로 있고, 아래에 홈 인디케이터가 있습니다.
**위로 쓸어올리거나 인디케이터를 누르면 홈으로 돌아갑니다.** 안드로이드 뒤로가기도 같습니다.

## 5. 정해야 할 것 세 가지

### Q1. 앱마다 주소를 줄까

| | 안 A — 주소 없이 | 안 B — 앱마다 주소 |
| --- | --- | --- |
| 새 라우트 | 0개 | `/clock` `/weather` `/resume` `/notes` |
| 공유 | 프로젝트·캘린더·음악만 (이미 있음) | 전부 |
| 뒤로가기 | 히스토리 항목을 넣어 처리 | 저절로 |
| 걸리는 것 | — | **데스크톱에서 그 주소가 무엇인지 정해야 합니다** |

권고는 **A** 입니다. 이력서·소개는 공유할 주소가 아니고(공유할 것은 프로젝트입니다),
새 주소를 만들면 데스크톱 서재에서도 그 주소가 무엇을 뜻하는지 정해야 합니다.

### Q2. 상세페이지를 어떤 모양으로 열까

| | 안 A — 전체화면 앱 | 안 B — Safari 시트 |
| --- | --- | --- |
| 모양 | 상태 표시줄 + 내용 + 홈 인디케이터 | 위에 주소 표시줄이 붙은 카드 |
| 인상 | 이 사이트가 만든 앱 | 링크를 눌러 웹을 연 것 |

권고는 **A** 입니다. 데스크톱에서는 "브라우저로 그 사이트를 연다"가 맞지만
(바탕화면 → 브라우저 → 사이트), 폰에서는 홈 화면에서 바로 앱이 열리는 쪽이
아이폰답고 화면도 한 겹 덜 먹습니다.

### Q3. 만들어 둔 세로 서재(820×1440)는 어떻게 할까

어제 만든 세로 무대는 **폰 홈 화면이 들어오면 쓸 자리가 없어집니다.**

| | 안 A — 지운다 | 안 B — 남긴다 |
| --- | --- | --- |
| | 좌표 한 벌만 관리 | 세로 태블릿(768~900px)에서 방을 보여줄 수 있음 |

권고는 **A** 입니다. 세로 태블릿은 드물고, 그 폭이면 폰 홈 화면도 어색하지 않습니다.
좌표를 두 벌 들고 있으면 물건을 옮길 때마다 두 번 고치게 됩니다.

## 6. 어떻게 갈아 끼우나 (기술)

### 셸을 둘로

`(site)/layout.tsx` 가 화면을 보고 `RoomShell` 또는 `PhoneShell` 하나만 그립니다.
둘 다 그려 놓고 CSS 로 숨기는 방법은 **못 씁니다** — 유튜브 iframe 이 둘이 되고,
DOM 에서 옮기면 음악이 끊깁니다(docs/06 M-07).

### 첫 프레임에 방이 비치지 않게

서버는 화면 크기를 모르므로 SSR 은 서재를 그립니다. 그대로 두면 폰에서
방이 한 번 번쩍하고 홈 화면으로 바뀝니다.

**인라인 스크립트로 그리기 전에 `html[data-shell]` 을 심습니다.**
인터페이퍼(02)가 다크모드 깜빡임을 막은 것과 같은 방법입니다 —
남의 저장소에서 본 수법을 여기서 씁니다.

### 다시 쓰는 것

| 그대로 | 무엇 |
| --- | --- |
| `IconArt` | 아이콘 SVG 여섯 |
| `useSky` | 실제 날씨·일출·일몰 |
| `DeskClock` 의 KST 계산 | 상태 표시줄·시계 위젯 |
| 상세페이지 전부 | 결정 대장 · 증거 · 테마 |
| `CalendarScreen` `MusicApp` | 캘린더·음악 앱 속 화면 |
| FLIP 모션 | 아이콘 자리에서 커지기 |

**새로 만드는 것은 홈 화면과 앱 껍데기뿐입니다.**

## 7. 순서

| # | 할 것 | 확인받을 것 |
| --- | --- | --- |
| 1 | 셸 분기 + 깜빡임 방지 · 세로 서재 정리(Q3) | 폰에서 홈 화면이 뜨는가 |
| 2 | 홈 화면 — 배경 · 상태 표시줄 · 위젯 둘 · 아이콘 · 독 | 크기·간격·실제 값 |
| 3 | 앱 껍데기 + 여는 모션 · 프로젝트 6 · 캘린더 | 열고 닫히는가 |
| 4 | 음악 앱 | 재생이 이어지는가 |
| 5 | 이력서 · 소개 앱 | 각각 |

**1~3 을 한 덩어리로 올립니다.** 홈 화면만 올리면 아이콘을 눌러도 아무 일이 없고,
"눌러도 아무 일 없는 것을 먼저 놓지 않는다"는 규칙과 어긋납니다.
그래서 **누를 수 있는 아이콘만** 올립니다 — 프로젝트 여섯과 캘린더.
음악은 유튜브 iframe 을 옮기면 소리가 끊겨(docs/06 M-07) 배선이 따로 필요하고,
이력서·소개는 화면을 새로 짜야 해서 다음으로 미룹니다.

**하나씩 올리고 확인받습니다**(docs/06 §1.5). 한 번에 다 올리면 지난번처럼
"1,2,3 모두 틀어져서 하나씩 조립하기가 힘들다" 가 됩니다.
